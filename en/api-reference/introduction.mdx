The MeiGen API lets you generate images and videos programmatically, plus [five dedicated image Skills](/en/api-reference/skills/overview). The Skills guide has its own upload, batch and requestId recovery contract; use it for those endpoints.

<Tip>
  **Prefer natural language?** If you use Claude Code, Cursor, or OpenClaw, try the [MCP Server](/en/mcp/overview) for AI-native image generation without writing HTTP code.
</Tip>

## Authentication

API requests require a Bearer token. There are two authentication methods:

### API Token (Recommended)

Use an API key that starts with `meigen_sk_`. Create one in a desktop browser on the [API Keys page](https://www.meigen.ai/profile/api-keys).

```bash
Authorization: Bearer meigen_sk_YOUR_API_KEY
```

<Warning>
  API tokens can only use **purchased credits**. Daily free credits are not available for API calls. Ensure your account has purchased credits before making API requests.
</Warning>

### Session Token

For meigen.ai's own browser integration, a logged-in session access token is accepted. Daily free credits cover **basic models only** (currently Flux 2 Klein and Agnes Image 2.5 Flash; Agnes Video 2.5 Flash has been temporarily unavailable since 2026-09-22, so no video model is on the basic tier right now); every other model always requires welcome or purchased credits. Third-party integrations should always use the API Token above.

## Base URL

```
https://www.meigen.ai/api
```

Before choosing a model, call [List Models](/en/api-reference/endpoint/models). The following example requires `gpt-image-2.5` to be active. GPT Image 2 remains available under its own ID and pricing when returned by that endpoint.

## Request Format

All request bodies must be sent as JSON with the `Content-Type: application/json` header.

```bash
curl -X POST https://www.meigen.ai/api/generate/v2 \
  -H "Authorization: Bearer meigen_sk_YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"prompt": "a minimalist logo", "modelId": "gpt-image-2.5", "resolution": "2K", "quality": "low", "modelVariant": "sunburst"}'
```

## Response Format

All responses return JSON. Successful responses include a `success: true` field:

```json
{
  "success": true,
  "generationId": "abc-123",
  "status": "processing"
}
```

Error responses include an `error` field:

```json
{
  "error": "Error description"
}
```

## Asynchronous Generation

Image generation is **asynchronous**. The flow is:

1. **Submit** a generation request → `POST /api/generate/v2`
2. **Poll** the status endpoint → `GET /api/generate/v2/status/:id`
3. **Read** the resulting `imageUrl` / `imageUrls` / `videoUrl` directly from the status response once `status === "completed"`.

### Polling Best Practices

- **Recommended interval**: 3 seconds between status checks
- **Stop when**: `status` is `completed` or `failed`
- While `status` is `processing`, the response includes `expectedWaitSeconds` (estimated remaining wait for this model and resolution) and `pollHintSeconds` (how many more seconds to keep polling — `0` means you can stop). Use these instead of a fixed timeout: actual time varies by model, resolution, and duration. Per-model typical times are listed on the [Models](/en/features/models) page.
- If your client stops polling early, the job still completes and is still charged — always poll until `status` reaches a terminal state.

## Caching

Some GET endpoints return cached responses:

| Endpoint | Cache Duration |
| --- | --- |
| `GET /api/models` | 1 hour (plus stale-while-revalidate) |
| `GET /api/images/:id` | 1 hour |
| `GET /api/skills` | Up to 5 minutes; errors are not cached |
| `POST` endpoints | No caching |

Model list changes — a new model, a retired one, a changed default — can therefore take up to an hour to become visible. Plan your own refresh cadence accordingly.

## Credits

Each generation deducts credits from your account. Image models charge per image (the amount can vary with resolution and quality); video models are billed per second or per generation, depending on the model. See the [Models](/en/features/models) page for the full per-model pricing table.

## Error Responses

The table below covers general generation. For Skills, use the [code-specific recovery rules](/en/api-reference/skills/overview#billing-and-errors); a 409 or 5xx is not an instruction to automatically create a new paid request.

| Status Code | Meaning |
| --- | --- |
| 400 | Bad request — invalid parameters |
| 401 | Unauthorized — invalid or missing token |
| 402 | Payment required — insufficient credits |
| 403 | Forbidden — model not available on this platform |
| 404 | Not found |
| 409 | Conflict — idempotency key already used, retry with a new one |
| 5xx | Server error — retry later; credits for a failed generation are automatically refunded |

For `POST /api/generate/v2`, error bodies include extra fields useful for debugging, and most carry a machine-readable `code` alongside the human-readable `error`:

| `code` | Status | Meaning |
| --- | --- | --- |
| `insufficient_credits` | 402 | Not enough usable credits for this request |
| `premium_model_paywall` | 402 | The selected model requires purchased credits (daily free credits don't apply) |
| `unsupported_quality` | 400 | The selected GPT Image model does not support this quality |
| `unsupported_model_variant` | 400 | Invalid variant, or `modelVariant` supplied for a model other than GPT Image 2.5 |
| `invalid_model` | 400 | Model is invalid, inactive, or reserved for a Skill workflow |
| `unsupported_duration` | 400 | This model doesn't support the requested duration |
| `unsupported_tier` | 400 | This model doesn't support the requested tier |
| `unsupported_resolution` | 400 | This model/tier doesn't support the requested resolution |
| `first_frame_required` | 400 | This model requires a first-frame image |
| `reference_video_not_supported` | 400 | This model/tier/resolution doesn't support reference-video continuation |
| `invalid_reference_video` | 400 | A `referenceVideos` entry couldn't be read or violates the selected model's per-clip limits. Read `capabilities.video.referenceVideo`: Seedance 2.5 accepts 2–30s / ≤200MB per clip; Seedance 2.0 accepts 2–15s / ≤50MB per clip. Every entry must be an `https://images.meigen.ai/...` URL — an arbitrary public URL fails here |
| `too_many_reference_videos` | 400 | More `referenceVideos` entries than this model allows — read `capabilities.video.referenceVideo.maxCount` (Seedance 2.5: 10; Seedance 2.0: 3) |
| `reference_video_total_seconds_exceeded` | 400 | The reference videos are individually valid but their durations add up past `capabilities.video.referenceVideo.maxTotalSeconds` (Seedance 2.5: 30s; Seedance 2.0: 15s) |
| `reference_audio_not_supported` | 400 | This model doesn't accept `referenceAudios` — read `capabilities.video.referenceAudio.enabled` |
| `invalid_reference_audio` | 400 | A `referenceAudios` entry isn't an `https://images.meigen.ai/...` URL, couldn't be read, isn't a wav or mp3 file, exceeds 15MB, or falls outside the per-clip duration range (Seedance 2.5: 2–30s; Seedance 2.0: 2–15s) |
| `too_many_reference_audios` | 400 | More `referenceAudios` entries than this model allows — read `capabilities.video.referenceAudio.maxCount` (Seedance 2.5: 10; Seedance 2.0: 3) |
| `reference_audio_total_seconds_exceeded` | 400 | The reference audio clips add up past `capabilities.video.referenceAudio.maxTotalSeconds` (Seedance 2.5: 30s; Seedance 2.0: 15s) |
| `reference_audio_requires_visual` | 400 | This model can't run on audio alone — send at least 1 reference image or 1 reference video alongside `referenceAudios` (Seedance 2.0; `capabilities.video.referenceAudio.requiresVisualReference`) |
| `reference_probe_timeout` | 503 | Server-side validation of the reference videos or audio did not finish within its budget (a CDN hiccup, a slow origin). **Nothing was charged**, and the body carries `retryable: true` — resubmit the identical request with the same `requestId` / `idempotencyKey` rather than creating a new attempt |
| `invalid_input` | 400 | The JSON body is malformed, or `referenceVideo` and `referenceVideos` were both sent with a different first element |
| `invalid_reference_url` | 400 | A `referenceImages` entry is not an accepted URL or base64 value |
| `frame_reference_limit` | 400 | `referenceMode: "frame"` allows at most 2 images — use `referenceMode: "content"` for more |
| `too_many_references` | 400 | Reference image count exceeds this model's limit |
| `too_many_characters` | 400 | At most 3 `[character:...]` references per generation |
| `character_not_found` | 400 | The referenced character doesn't exist or isn't owned by your account |
| `characters_not_supported` | 400 | This model doesn't support character references |
| `character_tier_required` | 400 | This character requires a higher tier |
| `model_not_available` | 403 | This model isn't available on the current platform |
| `idempotency_conflict` | 409 | This `idempotencyKey` already belongs to a request with different inputs. Never rotate the key automatically to get past this: look up the original request with `GET /api/generate/v2/requests/{requestId}` and reconcile your inputs. Use a new key only when the caller explicitly wants another paid generation |

Any other error — including all `5xx` responses — means the service is temporarily unavailable. Retry later; the credits for a failed generation are automatically refunded.

Errors without a `code` (such as an unsupported aspect ratio) should be handled by status code and `error` text.

```json
// 400 — unsupported aspect ratio
{
  "success": false,
  "error": "Aspect ratio 32:9 is not supported by GPT Image 2.0",
  "supportedRatios": ["1:1", "1:3", "16:9", "2:3", "21:9", "3:1", "3:2", "3:4", "4:3", "4:5", "5:4", "9:16", "9:21"]
}

// 400 — unusable reference image
{
  "success": false,
  "code": "invalid_reference_url",
  "error": "Reference images must be public HTTP(S) URLs or data:image/*;base64 inline data. Local file paths (e.g. C:/Users/...) and file:// URIs are not supported — upload the file to a public URL or pass base64 inline.",
  "received": "C:/Users/me/ref.png"
}

// 402 — premium model, no purchased credits
{
  "success": false,
  "code": "premium_model_paywall",
  "error": "Premium model requires purchased credits",
  "required": 10,
  "available": 4
}
```
