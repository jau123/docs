---
title: "List Models"
description: "Read available model IDs, defaults, pricing, and generation capabilities."
---

```
GET /api/models
```

Returns a list of all active AI models available for generation. Public endpoint, no authentication required.

The default active list contains public generation models. Skill-specific billing entries are excluded; use the Skills interface for those workflows. Read `is_default` for the current image default. GPT Image 2.5 can be requested only after it appears in this active list.

## Query Parameters

<ParamField query="media_type" type="string">
  Filter by output type: `image` or `video`. Omit to get both.
</ParamField>

<ParamField query="active" type="string" default="true">
  Pass `false` to include inactive models as well, including retired or not-yet-enabled models. Their presence in this expanded list does not make them callable; use the default active list for generation.
</ParamField>

## Response

`{ success: true, models: [...] }`. Each model object contains:

<ResponseField name="id" type="string">
  The unique model identifier. Use this as `modelId` when generating.
</ResponseField>

<ResponseField name="is_default" type="boolean">
  Whether this model is the current platform default for its media type. Do not infer the default from ordering, the model name, or a documentation example.
</ResponseField>

<ResponseField name="name" type="string">
  Display name.
</ResponseField>

<ResponseField name="provider" type="string">
  Model provider family (e.g. `OpenAI`, `Google`, `ByteDance`, `Midjourney`). Display only — not a request parameter.
</ResponseField>

<ResponseField name="credits_per_generation" type="number">
  A nominal fallback value. **Do not use it as the price for every configuration.** For GPT Image 2.5 and GPT Image 2, read `extra_config.pricing[resolution][quality]`. Use `extra_config.pricingPerSec` × `duration`, `extra_config.pricingPerCall[tier][duration]` for Veo 3.1, or the reference-video rules below. The authoritative charge is `creditsUsed` in the generate response.
</ResponseField>

<ResponseField name="supported_ratios" type="string[]">
  Aspect ratios accepted by `aspectRatio`. Seedance additionally accepts `"adaptive"`.
</ResponseField>

<ResponseField name="max_reference_images" type="number">
  For image models, the maximum number of reference images accepted (`0` means none). For video models, this is the first/last-frame slot limit. Seedance content-reference mode uses `extra_config.maxContentReferenceImages` instead.
</ResponseField>

<ResponseField name="media_type" type="string">
  `"image"` or `"video"`.
</ResponseField>

<ResponseField name="estimatedTiming" type="object">
  Estimated generation time for this model's default tier/resolution, in seconds: `{ p50, p90 }`. Calibrated from production data — use it to set user expectations, not as a hard deadline. Actual time still varies by resolution, tier, and duration.
</ResponseField>

<ResponseField name="capabilities" type="object">
  Stable, forward-compatible capability contract. `capabilities.video` is always an object: check `capabilities.video.valid` to distinguish video models (`true`) from image models (`false`). When valid, it describes output duration options, reference-video and reference-audio limits, billing mode, and whether a first frame is required. **Do not test `if (capabilities.video)`** because the object is also present on image models. New integrations should read this contract instead of reconstructing it from `extra_config`.

  `capabilities.video.referenceVideo` carries `enabled`, `minSeconds` and `maxSeconds` (per clip), plus `maxCount` and `maxTotalSeconds` for the whole array — Seedance 2.5 allows 10 clips totalling 30s, Seedance 2.0 allows 3 clips totalling 15s. `capabilities.video.referenceAudio` has the same shape plus `formats` (`["wav", "mp3"]`) and `requiresVisualReference`: when it is `true` (Seedance 2.0) the request must also carry at least one reference image or reference video, so audio-only generation is rejected. Current responses always include both objects. A response body cached before 2026-09 may still lack them, so treat a missing `referenceVideo` or `referenceAudio` as `{ "enabled": false }` rather than as "unlimited". Reference audio never affects billing.
</ResponseField>

<ResponseField name="extra_config" type="object">
  Model-specific configuration, kept for backward compatibility. New integrations should prefer `capabilities.video` for video-capability shape (see above); the pricing keys below are still only available here. Keys you may rely on:

  | Key | Used by | Description |
  | --- | --- | --- |
  | `resolutions` | Image / video | Allowed values for `resolution` (`"1K"` / `"2K"` / `"3K"` / `"4K"` for image, `"480p"` / `"720p"` / `"1080p"` / `"4k"` for video) |
  | `qualities` | Image models with quality options | Accepted `quality` values; GPT Image 2.5 has `low`, `medium`, `high`, `xhigh`, `max` |
  | `defaultQuality` | Image models with quality options | Used when `quality` is omitted or `auto`; GPT Image 2.5 is configured as `low` |
  | `variants` / `defaultVariant` | GPT Image 2.5 | Accepted `modelVariant` values (`sunburst`, `flare`) and the configured default (`sunburst`) |
  | `defaultResolution` | Image / video | Resolution used when the request omits `resolution` |
  | `pricing` | Image models with variable prices | Credits by resolution then quality, for example `pricing["2K"]["low"]`; some models expose a number per resolution |
  | `tierResolutions` | Seedance 2.0 | Resolutions actually available in each tier, keyed by tier. Takes precedence over the top-level `resolutions` |
  | `tiers` | Seedance 2.0 / Veo 3.1 | Available tiers, selected via `tier` (Seedance 2.0: `mini` / `fast` / `pro`; Veo 3.1: `fast` / `pro`) |
  | `durations` | Video models | Allowed values for `duration` (seconds) |
  | `pricingPerSec` | Seedance 2.5 / Seedance 2.0 / Grok Video 1.5 / Agnes Video 2.5 Flash | Per-second direct-generation rate, keyed by resolution — or by tier then resolution on models that expose tiers |
  | `pricingPerCall` | Veo 3.1 | Credits per generation, looked up by tier then `duration`. Mutually exclusive with `pricingPerSec`; when present it takes precedence |
  | `pricingPerSecWithVideo` | Seedance 2.5 / Seedance 2.0 | Per-second rate used when **any** reference video is present, keyed by resolution — or by tier then resolution. Reference audio alone does not switch to this rate; an audio-only request bills at `pricingPerSec` |
  | `minBillableTable` | Seedance 2.5 / Seedance 2.0 | Minimum billable seconds keyed by output `duration`; bill `max(sum of reference video durations + output, minimum)`. Reference audio durations are never included |
  | `maxContentReferenceImages` | Seedance 2.5 / Seedance 2.0 | Maximum images accepted when `referenceMode` is `content`; separate from the first/last-frame slots in `max_reference_images` |

  The pricing-related keys above are part of the contract. Other keys may appear and are informational.
</ResponseField>

<Note>
  Example shows two representative model configurations with a partial `extra_config` for brevity. It does not assert that either model is currently enabled or the default. Timing values are an illustrative production snapshot and may change as estimates are recalibrated. The live endpoint returns all active models with their current full configuration. Responses are cached for 1 hour (plus stale-while-revalidate), so newly added or retired models can take up to an hour to appear.
</Note>
