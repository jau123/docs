## New connection: use account sign-in

For ChatGPT, [install MeiGen from the official ChatGPT store](/en/mcp/overview#chatgpt) and sign in. Other users should add the Streamable HTTP server `https://www.meigen.ai/api/mcp` in an OAuth-capable MCP host, then choose **Connect / Authenticate** and approve the MeiGen account connection. No API key or Node.js is needed. See [remote setup](/en/mcp/remote) for Claude, Codex, Cursor and other compatible hosts.

If the host cannot authenticate with OAuth, use a compatible client or the official ChatGPT plugin. API keys are only retained for existing legacy integrations, not offered as an alternative for new users. Do not paste credentials into chat.

Private favorites, boards, history, prompt details and saving are available through standard remote MCP with OAuth. Local npm and API keys cannot access them. These tools are still pending approval in the official ChatGPT store update; installing the currently published plugin does not enable them.

## Ask an assistant to connect

```text
Connect MeiGen MCP at https://www.meigen.ai/api/mcp with remote OAuth.
Preserve other servers and reuse an existing MeiGen entry. When switching from a
fixed API key, remove its Authorization header and let me sign in through the host.
Do not create a new API key or ask for credentials in chat. Keep a working legacy
or BYOK setup only when needed, and do not add duplicate MeiGen tools.
After reconnecting, call list_skills and report the result. Do not upload,
generate or spend credits just to verify setup. Explain any unverified step.
```

## Existing local integrations and BYOK

The following configuration is for maintaining an existing stdio/API-key integration or an explicitly selected OpenAI-compatible image provider. Local npm has no OAuth login and does not expose private account-library tools. It can prepare readable local files, save ordinary generation results, enhance prompts and store machine-local preferences.

<Note>
  npm **3.0.0 is the current major release**. Before upgrading, read the [3.0 migration notes](/en/mcp/comfyui): ComfyUI and the bundled prompt library are removed, with no offline search fallback. The examples below pin this version explicitly.
</Note>

Node.js 22+ is recommended. Preserve an existing key privately as `MEIGEN_API_TOKEN`; do not create a new MeiGen key for these examples. The snippets below show relevant fields only; do not replace an existing entry or configuration file with them.

```json
{
  "mcpServers": {
    "meigen": {
      "command": "npx",
      "args": ["-y", "meigen@3.0.0"]
    }
  }
}
```

Set existing credentials in the MCP process environment or host private settings, not in shared JSON. Private local configuration at `~/.config/meigen/config.json` remains compatible. Changes require restarting/reconnecting the host.

### Existing editor connections

For an existing Cursor, VS Code, Windsurf, Roo or Claude connection, edit its MeiGen entry manually. Change only the package argument in `args` to `meigen@3.0.0`; preserve the command, other arguments, `env`, environment forwarding, timeouts, host-specific settings and all other MCP entries. Keep any existing private credentials in place.

Do not run the published 2.0.2 initializer against existing configuration: it can replace the MeiGen entry rather than preserve its settings. If the command uses an unfamiliar wrapper or has no identifiable MeiGen package argument, leave it unchanged and inspect that host's configuration before editing. Keep an explicit version pin instead of an unversioned package or `@latest` to avoid an unintended future major upgrade. New connections use [remote OAuth](/en/mcp/remote).

### Existing Codex stdio configuration

New users should use [remote OAuth](/en/mcp/remote). Existing local integrations can keep this entry instead of a duplicate remote entry:

```toml
[mcp_servers.meigen]
command = "npx"
args = ["-y", "meigen@3.0.0"]
env_vars = ["MEIGEN_API_TOKEN"]
startup_timeout_sec = 90
tool_timeout_sec = 240
```

The host must inherit the existing variable; a project `.env.local` is not automatically loaded. Omit `env_vars` for anonymous public discovery if no variable exists. Longer video jobs may need more time; recover interrupted tasks with the original generationId or persisted requestId instead of starting a new paid attempt.

### Existing Claude and OpenClaw plugins

The Claude marketplace and OpenClaw bundle may include a local stdio server. Their versions and instruction files update separately from npm. Inspect the installed connection and keep one active MeiGen server when switching to OAuth. A standalone ClawHub Skill supplies instructions; it does not prove a live MCP connection. See the [repository guide](https://github.com/jau123/MeiGen-AI-Design-MCP#quick-start) for the selected distribution.

### Hermes Agent (NousResearch)

New MeiGen connections should use [remote OAuth](/en/mcp/remote). For an existing local Hermes integration that waits for long video jobs, merge these timeouts into its `~/.hermes/config.yaml` entry, keeping its existing private environment settings:

```yaml
mcp_servers:
  meigen:
    command: "npx"
    args: ["-y", "meigen@3.0.0"]
    timeout: 2700
    connect_timeout: 120
```

`timeout: 2700` allows up to 45 minutes for a tool call; `connect_timeout: 120` allows time for the first npm download. They are suggested settings for long waits, not a generation deadline or completion guarantee. See [Hermes MCP configuration](https://hermes-agent.nousresearch.com/docs/reference/mcp-config-reference/).

A host timeout does not cancel or refund an accepted task. Prefer `wait: false` with a persisted UUID `requestId` and `download: false` for composed jobs. Recover with `check_generation` using the original generationId or requestId; if resubmission is required, preserve that ID and exact inputs. See [workflow recovery](/en/mcp/composable-workflows).

### Legacy CLI

An existing CLI integration may continue using its privately configured `MEIGEN_API_TOKEN`:

```bash
npx -y meigen@3.0.0 gen --prompt "a ceramic coffee mug in soft window light"
npx -y meigen@3.0.0 gen -p "product hero shot" --ref ~/Desktop/bottle.jpg
npx -y meigen@3.0.0 gen --help
```

These generation examples are paid actions, not connection tests. `--json` returns structured output; `--no-wait` submits without polling. Preserve returned task IDs and exact inputs for recovery.

### OpenAI-compatible ordinary images

For an explicitly selected BYOK provider, retain `OPENAI_API_KEY`, `OPENAI_BASE_URL` and `OPENAI_MODEL` in private local settings. Use that provider's supported models and billing. BYOK does not provide MeiGen videos, the five dedicated Skills or private library access. In 3.0.0, local provider priority is MeiGen (existing legacy key), then OpenAI-compatible; the removed ComfyUI provider is rejected rather than redirected to a paid provider.

## Output directories

Ordinary local generation and CLI calls can save results. Dedicated Skills return URLs/resources; download them explicitly if needed.

| Type | Default | Override | Linux fallback |
| --- | --- | --- | --- |
| Images | `~/Pictures/meigen/` | `MEIGEN_OUTPUT_DIR` | `XDG_PICTURES_DIR` |
| Videos | `~/Movies/meigen/` | `MEIGEN_VIDEO_OUTPUT_DIR` | `XDG_VIDEOS_DIR` |

## Verify and recover

After connecting, ask “List MeiGen's available Skills and current prices” and verify a successful `list_skills` call. This public check does not prove account authorization or paid balance. Do not generate merely to test a connection.

For missing authorization, reconnect through OAuth. For existing legacy integrations only, privately check the configured key. For insufficient credits, use the connected account's [Profile → Top Up](https://www.meigen.ai/profile); generation uses purchased credits, not daily free credits. Follow actual `list_models` / `list_skills` prices.

An interrupted ordinary task uses `check_generation`; a Skill uses `check_skill` with its original receipt and exact inputs. Follow returned actions for upload errors, resize consent, price changes and refunds. See the [workflow contract](/en/mcp/composable-workflows) and [Skills guide](/en/api-reference/skills/overview).
