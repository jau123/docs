---
title: "模型列表"
description: "查询可用模型 ID、默认设置、积分价格和生成能力。"
---

```
GET /api/models
```

返回所有可用于生成的活跃 AI 模型列表。公开端点，无需认证。

默认活跃列表只包含公开生成模型，不包含技能专属计费项；此类工作流请通过技能界面使用。当前图片默认模型由 `is_default` 标记。只有活跃列表返回 GPT Image 2.5 后，才可请求该模型。

## 查询参数

<ParamField query="media_type" type="string">
  按输出类型过滤：`image` 或 `video`。不传则两类都返回。
</ParamField>

<ParamField query="active" type="string" default="true">
  传 `false` 可一并返回未启用模型，包括已下线或尚未开放的模型。出现在扩展列表中不代表可调用；生成时请使用默认活跃列表。
</ParamField>

## 响应

`{ success: true, models: [...] }`。每个模型对象包含：

<ResponseField name="id" type="string">
  模型唯一标识符。生成时用作 `modelId`。
</ResponseField>

<ResponseField name="is_default" type="boolean">
  是否为该媒体类型的当前平台默认模型。不要根据排序、型号名称或文档示例推断默认值。
</ResponseField>

<ResponseField name="name" type="string">
  显示名称。
</ResponseField>

<ResponseField name="provider" type="string">
  模型供应商家族（如 `OpenAI` / `Google` / `ByteDance` / `Midjourney`）。仅供展示，不是请求参数。
</ResponseField>

<ResponseField name="credits_per_generation" type="number">
  名义兜底值，不能作为所有配置的价格。GPT Image 2.5 与 GPT Image 2 应读取 `extra_config.pricing[resolution][quality]`。视频使用 `extra_config.pricingPerSec` × `duration`、Veo 3.1 的 `pricingPerCall[tier][duration]` 或参考视频计费规则。实扣以生成响应中的 `creditsUsed` 为准。
</ResponseField>

<ResponseField name="supported_ratios" type="string[]">
  `aspectRatio` 接受的取值。Seedance 另支持 `"adaptive"`。
</ResponseField>

<ResponseField name="max_reference_images" type="number">
  图片模型可接受的最大参考图数量（`0` 表示不支持）；视频模型中表示首帧/末帧槽位上限。Seedance 内容参考模式应读取 `extra_config.maxContentReferenceImages`。
</ResponseField>

<ResponseField name="media_type" type="string">
  `"image"` 或 `"video"`。
</ResponseField>

<ResponseField name="estimatedTiming" type="object">
  该模型默认档位/分辨率的预估生成耗时（秒）：`{ p50, p90 }`。基于生产数据校准，用于设置用户预期，不是硬性截止时间；实际耗时仍会随分辨率、档位、时长变化。
</ResponseField>

<ResponseField name="capabilities" type="object">
  稳定、向前兼容的能力契约。`capabilities.video` 始终是对象：用 `capabilities.video.valid` 区分视频模型（`true`）与图片模型（`false`）。`valid` 为真时，该对象描述输出时长、参考视频限制、计费模式和是否必须提供首帧。**不要写 `if (capabilities.video)`**，因为图片模型也会返回该对象。新集成应读取这份契约，不要从 `extra_config` 自行拼装视频能力。
</ResponseField>

<ResponseField name="extra_config" type="object">
  模型特定配置，仅为兼容旧客户端保留。新集成的视频能力形状请优先用上面的 `capabilities.video`；下列定价相关字段仍只能从这里取。可放心使用的字段：

  | 字段 | 适用模型 | 说明 |
  | --- | --- | --- |
  | `resolutions` | 图片 / 视频 | `resolution` 允许的取值（图片 `"1K"` / `"2K"` / `"3K"` / `"4K"`，视频 `"480p"` / `"720p"` / `"1080p"` / `"4k"`）|
  | `qualities` | 支持质量选项的图片模型 | `quality` 的合法值；GPT Image 2.5 为 `low`、`medium`、`high`、`xhigh`、`max` |
  | `defaultQuality` | 支持质量选项的图片模型 | 省略 `quality` 或传 `auto` 时使用；GPT Image 2.5 配置为 `low` |
  | `variants` / `defaultVariant` | GPT Image 2.5 | `modelVariant` 的合法值（`sunburst`、`flare`）与配置默认值（`sunburst`） |
  | `defaultResolution` | 图片 / 视频 | 请求省略 `resolution` 时使用的分辨率 |
  | `pricing` | 按配置计价的图片模型 | 按分辨率与质量取积分，如 `pricing["2K"]["low"]`；部分模型每个分辨率直接对应一个数字 |
  | `tierResolutions` | Seedance 2.0 | 各档位实际可用的分辨率，按档位分级。优先于顶层 `resolutions` |
  | `tiers` | Seedance 2.0 / Veo 3.1 | 可选档位，通过 `tier` 选择（Seedance 2.0：`mini` / `fast` / `pro`；Veo 3.1：`fast` / `pro`）|
  | `durations` | 视频模型 | `duration` 允许的取值（秒）|
  | `pricingPerSec` | Seedance 2.5 / Seedance 2.0 / Grok Video 1.5 / Agnes Video 2.5 Flash | 直接生成每秒积分，按分辨率分级；有档位的模型先按档位再按分辨率 |
  | `pricingPerCall` | Veo 3.1 | 每次生成消耗的积分，按档位再按 `duration` 二维查表。与 `pricingPerSec` 互斥，存在时优先 |
  | `pricingPerSecWithVideo` | Seedance 2.5 / Seedance 2.0 | 提供 `referenceVideo` 时的每秒积分，按分辨率或档位 + 分辨率分级 |
  | `minBillableTable` | Seedance 2.5 / Seedance 2.0 | 按输出 `duration` 的最低计费秒数；计费取 `max(参考 + 输出, 最低值)` |
  | `maxContentReferenceImages` | Seedance 2.5 / Seedance 2.0 | `referenceMode` 为 `content` 时的图片上限；与 `max_reference_images` 的首帧/末帧槽位分开 |

  上述定价相关的键属于契约的一部分；响应里可能出现其它键，仅供参考。
</ResponseField>
